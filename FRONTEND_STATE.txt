=============================================================
FRONTEND PRODUCT ROLE
=============================================================
The frontend now supports one core loop:

Moment -> Mission -> Puzzle -> Coaching

Current implementation status:
- discovery exists
- explanation exists
- puzzle interaction exists
- post-puzzle coaching is partial and mostly embedded in puzzle scoring/result UI

The next UX goal is to make the connection between moment and puzzle more explicit,
so the user quickly understands:
- what happened
- what the tactical problem is
- what they are being asked to solve

=============================================================
PAGES
=============================================================
LeagueSelect
- Pick Premier League or Serie A

ClubSelect
- Search and select a club
- Fetches `/api/clubs`

ModeSelect
- Choose Simple or In-Depth
- Controls whether `/api/story` returns 5 or 10 moments

QuerySelect
- Pick a moment type:
  Dramatic, Dominant, Comeback, Under Pressure, Turning Points, Surprise

Moments
- Fetches `/api/story`
- Displays moment cards
- Caches query results in session storage
- Supports regenerate and tab switching across themes

MomentDetail
- Fetches `/api/explain`
- Shows selected moment plus explanation
- Currently acts as the bridge from story to puzzle
- CTA sends the user into `/puzzle`

Puzzle
- Fetches `/api/network`
- Renders tactical puzzle using two synchronized pitch views
- Lets the user build and submit a passing route under pressure

=============================================================
API ENDPOINTS CONSUMED
=============================================================
GET  /api/clubs?league=PL|SA
  -> club selection list

GET  /api/story?team=&league=&mode=&queryType=
  -> retrieved moments for current team and theme

POST /api/explain
  -> grounded explanation for selected moment

GET  /api/network?escapingTeam=&pressingTeam=&league=&minute=&homeGoals=&awayGoals=
  -> escape and pressing graphs for puzzle

=============================================================
TACTICAL PUZZLE
=============================================================
File:
frontend/src/pages/Puzzle.tsx

The puzzle is the main interaction layer of the product.

Current structure:
- left panel: `PressureMap`
- right panel: `PitchGraph`
- bottom/result section: sequence feedback and scoring

Current local state in Puzzle.tsx:
- `userSequence`
- `ballCarrier`
- `escapeGraph`
- `pressGraph`
- `submitted`
- `optimalPath`
- `hoveredEdge`
- `clickFeedback`

Current frontend-derived values:
- `optimalNodeId`
- `vacatedZones`
- `blockerMap`
- `progressionValue`
- `userScore`
- `optimalScore`

Current rules:
- all nodes are clickable
- max 5 nodes in sequence
- cannot revisit a node
- edges missing from graph fall back to default risk

Note:
The puzzle still contains significant frontend game logic. Long-term,
more of this should move into backend-owned puzzle state and evaluation.

=============================================================
CURRENT FRONTEND DIRECTION
=============================================================
The frontend should increasingly optimize for:
- less reading before interaction
- clearer tactical mission framing
- stronger bridge from moment to puzzle
- better coaching after submission

The ideal experience is:
- user sees a real moment
- understands the tactical problem quickly
- tries to solve it
- learns one football idea through guided feedback

That is the current product direction for the frontend.
